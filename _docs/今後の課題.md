# MarkdownViewer 今後の課題

最終更新: 2026-03-08

## 1. セキュリティ強化

### 1-1. CDN依存の解消
- 対応済み: `marked` / `Prism` / `Mermaid` / `github-markdown-css` をアプリ同梱へ移行。
- 現状: WebView2 の仮想ホスト経由でローカル配信。
- 関連ドキュメント: `THIRD-PARTY-NOTICES.md` を追加済み。
- 関連ドキュメント: `_docs/ライブラリ更新手順.md` を追加済み。
- 残課題: 更新時の確認項目を運用しながら必要に応じて補強。

### 1-2. Mermaid設定の見直し
- 対応済み: `securityLevel: 'strict'` を採用。
- 現状: Mermaid は `strict` / `neutral` テーマで初期化。
- 残課題: 実運用で描画できない Mermaid 記法が出た場合のみ個別検討。

### 1-3. Markdown HTMLのサニタイズ
- 対応済み: `DOMPurify` による HTML サニタイズを導入。
- 現状: 既定ではサニタイズ有効。必要時のみ `Unsafe` トグルでセッション中だけ無効化可能。
- 残課題: 許可タグ・属性の見直しが必要になった場合のみ個別調整。

### 1-4. CSPの厳格化
- 現状: `unsafe-inline` を許可。
- リスク: スクリプト注入耐性が弱い。
- 対応案: inline依存を減らし、より厳格なCSPへ移行。

## 2. 機能・UX改善

### 2-1. 履歴復元ロジック
- 現状: 起動時は履歴先頭1件のみ自動試行。
- 改善案: 先頭が欠損時に次の履歴を順に試行。

### 2-2. 外部リンク制御の拡張
- 現状: `http/https` のみ標準ブラウザで起動。
- 改善案: 許可スキームの設定化（例: `mailto:` の扱い）。

## 3. 配布・運用

### 3-1. 署名戦略
- 現状: ハッシュ公開で改ざん検証を実施。
- 今後: OSS無償署名サービス（例: SignPath Foundation）導入を検討。

### 3-2. リリース自動化
- 現状: `scripts/release.ps1` で手動実行。
- 改善案: GitHub Actions連携でタグ起点の自動ビルド/ハッシュ生成。

## 優先度（提案）

1. CSP厳格化
2. 履歴復元ロジック改善
3. CIによるリリース自動化
